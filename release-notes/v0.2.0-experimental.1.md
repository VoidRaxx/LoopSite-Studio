# LoopSite Studio 0.2.0 Experimental 1

First **official experimental prerelease candidate** of LoopSite Studio for testing on Windows and Linux. This release is not intended for production systems.

## Added
- Native desktop project management and isolated PHP/static local development servers.
- PHP runtime discovery and an opt-in PHP/Caddy installation assistant for supported package managers.
- Monaco-based code editor with multiple file tabs, split views, search/replace, and guarded saves.
- Native SQLite database creation, tables, basic row editing, guarded deletion with archive, and database-file import/export.
- MariaDB/MySQL localhost connection, database/table creation, previews, basic row insertion and editing, and confirmed database deletion.
- Local HTTP routing through externally installed Caddy.
- Searchable, severity-highlighted live server logs with copy and clear actions.
- Twelve coordinated UI color schemes, system theme following, and Compact/Normal/Large interface sizes.
- English-first language selection (English, German, French, Spanish, Portuguese, Italian, Japanese, Simplified Chinese); initial translations are partial.
- Startup update checks with changenotes, feature/security labels, and Update/Later/Skip choices.
- Windows NSIS setup and ZIP portable build; Linux DEB, RPM and native Arch package build targets; portable AppImage build target.
- Version display in the application sidebar and repository community/security/accessibility documentation.

## Changed
- Renamed the application's former HybrideUniverse appearance preset to **Default**. Existing theme preferences are migrated.
- Release delivery now requires an English changelog, explicit approval and separate signed update artifacts.
- Normal CI builds validate formats without publishing downloadable installers.
- Portable builds use an isolated `portable-data` directory alongside the portable executable or AppImage.

## Fixed
- Windows PHP CLI router path handling for the `\\?\C:\...` extended-path prefix.
- Improved protection against unsafe SQLite imports, unintended overwrites, and invalid database identifiers.
- Preserved large MariaDB integer identifiers without JavaScript rounding.
- Corrected frontend rendering problems and made log presentation more readable.

## Security
- No specific security advisory is claimed for this feature prerelease.
- Local servers bind to loopback by default; LAN access is opt-in.
- Destructive database actions require explicit confirmation. MariaDB's `DROP DATABASE` is permanent.
- In-app installation requires Tauri-signed release packages; portable and unsupported package-manager installations use manual release downloads.

## Known Issues
- **Experimental software:** Interfaces and data formats can change, and some workflows still need real-world compatibility testing.
- Managed HTTPS certificates, automatic MariaDB server installation, and complete runtime isolation are not available.
- A running MariaDB/MySQL server must already be installed; registered local services can be started when permissions allow.
- SQL management is intentionally limited. Some tables cannot be edited if they lack a supported unique primary key.
- Interface translations are incomplete; some screens still show German or English regardless of the selected language.
- Linux AppImage requires a compatible host environment and a writable folder for truly portable data storage; some systems need FUSE compatibility.
- Projects stored outside `portable-data` remain external and are not automatically copied when the portable app is moved.
- Portable applications and Linux system packages use manual update installation. Self-installing updates additionally require signed release setup.
- Network-exposed production hosting and production database administration are **not** recommended.
